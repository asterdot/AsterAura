### 2.3 协议：未知接口返回 404

`ServerHost.HandleApiAsync` 的 `handler is null` 分支由 HTTP 200 改为 **404**，
**响应体结构保持不变**：`{"ok":false,"reason":"不认识这个接口：<path>"}`。

配套：`HttpUtil` 新增带状态码的重载，既有重载行为不变（默认仍是 200）：

```csharp
public static Task JsonAsync(HttpContext ctx, int status, JsonNode? body)
    => SendAsync(ctx, status, body?.ToJsonString() ?? "null", "application/json; charset=utf-8");
```

**前端零影响**（已只读核查确认）：`assets/public/app.js` 里读 `r.status` 的只有一处（401 特殊处理），
其余判断全走响应体的 `ok` 字段，404 不会命中该分支，且前端无任何 `status === 200` 分支。

## 3. 迁移脚本原子 staging 版（已完成）

**状态：已完成**。`tools/migrate-legacy.ps1` 已整体重写（331 → 473 行），原生支持「先拷到 staging → 在 staging 内改写与严格对账 → 通过后才原子落到 dest」。

**为什么重写而不是合并**：原草稿 `tools/migrate-legacy-staging.ps1` 存在三个真问题，直接搬过来会引入回归：

| 缺陷 | 原草稿行为 | 现在的修法 |
|---|---|---|
| A. `Move-Item` 语义 | 目标目录已存在（哪怕是空目录）时，`Move-Item $staging $destReal` 会把 staging 变成 `$destReal\<staging名>` 子目录，而不是替换 | 改用 `[System.IO.Directory]::Move`；目标已存在时先 rename 到同名备份目录（同卷 rename），再 rename staging → dest；失败自动回滚，备份路径打印到 stdout |
| B. `-MergeExisting` 与原子替换互斥 | 2f 允许并入非空目标，但原子换目录那步遇到目标已存在就 exit 2 —— 只要并入模式就必然失败，staging 还留在盘上 | 合并模式下，目标中更新的文件归类为 `superseded-newer`（接受目标版本，不算冲突），并把实际哈希写回期望清单，使切换前对账与切换后终检语义一致 |
| C. GBK 坏字节 | 文件混入了 GBK 字节，整体不是合法 UTF-8，注释与提示全是乱码 | 全量重写为 UTF-8 with BOM（PS 5.1 读中文注释的硬要求），`\ufffd` 计数 0，PS Parser 0 错误 |

**独立审查后又修的三处**（verifier 只读审查发现）：

| 缺陷 | 位置 | 问题 | 修法 |
|---|---|---|---|
| A（审查版） | `migrate-legacy.ps1` 原 398 行 | `[System.IO.Directory]::Move($destReal, $backupReal)` 未包 try/catch，被进程占用时 exit **1**（违反退出码合同），且不打印 staging 路径、manifest 不落盘 | 包 try/catch → 打印 staging 路径 + `Write-ResultManifest` + exit 2 |
| B（审查版） | 原 260 / 269 行 | robocopy 返回码按 `>= 8` 判定，但 rc 是**位掩码**，bit 4 = 有文件/目录复制失败。源里 `media/in.txt` 是目录、目标里 `media` 是文件时 rc=4 被当成功放行 → **目标原文件被静默顶掉，只剩在 backup 里，用户无感知** | 改为位掩码判定 `($rc -band 4) -ne 0 -or ($rc -band 8) -ne 0 -or ($rc -band 16) -ne 0`；rc=1/2/3 属正常 |
| C（审查版） | 原 301 / 358 行 | `superseded-newer` 条目只记 path/status/detail，且已把 `$e.sha256` 覆盖成目标哈希 → manifest 无法还原源版本哈希，审计链断 | 覆盖前先存 `$srcSha = $e.sha256`，条目增加 `sourceSha256` 字段 |

附带：DryRun 不再输出目标目录的条目数（合同要求不输出真实数据统计），改为定性的「已存在（非空）」。

**行为测试**：新增 `tools/test-migrate-legacy.ps1`（530 行，21 个用例组 / 79 条断言），全绿。
覆盖：DryRun 不落盘、缺参 exit 3、源不存在 exit 3、源=目标/双向嵌套 exit 4、目标非空无 `-MergeExisting` exit 4 且目标未改动、正常 Apply 逐文件 SHA-256 一致、`-Port` 改写且 config.json 无 BOM 可解析、`-MergeExisting` 三条件（旧文件保留 / 新文件并入 / 更新文件不被覆盖）、源文件锁定→预检失败 exit 2 且不落盘、幂等重跑、`PUBLICATION_DENIED` exit 7、ManifestPath 已存在 exit 4 / 正常写入无 BOM、**目标为空目录→数据落在目标本身而非子目录**、目标被占用→exit 2 + 打印 staging + 目标完好、**文件/目录同名冲突→exit 2 且不静默替换**、manifest 含 `sourceSha256`、DryRun 不泄露条目数、脚本编码自检。

跑法：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-migrate-legacy.ps1   # 期望 79/79 ALL PASS
```

**已知遗留（低风险，均为有意设计）**：
- 每次成功的 `-MergeExisting` Apply 会在 dest 父目录留一个 `*.migbackup-*` 备份目录（路径会打印），无自动清理，需手动清理。
- 切换后终检（3i）失败时 exit 2 且不自动回滚 —— 此时数据已在 dest，backup 保留，人工可恢复。这是原子切换的固有边界。
