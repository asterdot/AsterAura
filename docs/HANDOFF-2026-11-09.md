- `accounts.json` 成为账号的**唯一事实源**：所有账号 `role=owner` / `level=full`，会话 `role=owner`。
- 存量 `accounts.json` 缺 `role` 字段的账号，读取时**归一为 owner**，不会掉级。
- 多账号并存互不冲突，注册不再拒绝第二个账号。
- **访客机制退休**：删除 `/api/guests` 的 GET/POST/PATCH/DELETE；`AuthService` 的 `ListGuests` / `CreateGuest` / `UpdateGuest` / `DeleteGuest` 退役。
- 保留 `users.json` 的**只读**解析（`GuestsOf` / `IsLegacySubject` / `DisplayNameOf`）作迁移期兼容；旧 guest 记录**不删不改**；旧 guest 会话**不会被判成 account**。
- 前端清空访客残留：面板、接口调用、样式、文案、「客人xxx」说话人显示逻辑。
  - `#link-legacy` 是「本机旧账号登录」**迁移入口**，不是访客入口，**保留**。

涉及文件：`src/AuraChat.Core/Auth/AccountService.cs`（新）、`AuthService.cs`、`src/AuraChat.Server/ApiContext.cs`、`Routes/{SessionRoutes,V2AuthRoutes,MemoryRoutes}.cs`、`src/AuraChat.Features/Chat/ToolSchemas.cs`、`src/AuraChat.Features/Media/DiaryService.cs`、`assets/public/**`

### 2.2 生命状态（修了一个真 bug）

原 bug：`MoodService.Save()` 只写 `mood.json`，但 `Current()` 优先读 `LifeStateService`（`state.json`），
导致面板「重置 / Nudge」和聊天后的激素更新**对实际状态无效**。

修法：
- `state.json` 升为**唯一事实源**，`mood.json` 降级为历史层。
- `LifeStateService` 新增公开方法 `UpdateHormones(Hormones h)`。
- `MoodService.Save()` 末尾调用它，把新值写回 `state.json`，读写对称。

涉及文件：`src/AuraChat.Features/Life/LifeState.cs`（新）、`LifeStateService.cs`（新）、`MoodService.cs`

### 2.3 协议：未知接口返回 404

`ServerHost.HandleApiAsync` 的 `handler is null` 分支由 HTTP 200 改为 **404**，
**响应体结构保持不变**：`{"ok":false,"reason":"不认识这个接口：<path>"}`。

配套：`HttpUtil` 新增带状态码的重载，既有重载行为不变（默认仍是 200）：

```csharp
public static Task JsonAsync(HttpContext ctx, int status, JsonNode? body)
    => SendAsync(ctx, status, body?.ToJsonString() ?? "null", "application/json; charset=utf-8");
```

**前端零影响**（已只读核查确认）：`assets/public/app.js` 里读 `r.status` 的只有一处（401 特殊处理），
其余判断全走响应体的 `ok` 字段，404 不会命中该分支，且前端无任何 `status === 200` 分支。

新增测试：`src/AuraChat.Tests/ApiProtocolE2eTests.cs` → `UnknownApiRoute_Returns404_AndErrorBody`（覆盖 `/api/guests` 与 `/api/__nope__`）

### task-6 · 统一 API 错误响应状态码

**背景**：`ServerHost.cs` 里有两处错误响应仍是 HTTP 200 + `{"ok":false,...}`：
- 顶层异常处理分支（原 `:139` 附近）
- handler 内异常处理分支（原 `:159` 附近）

现状语义不对称：接口不存在 → 404；接口存在但内部出错 → 200。

**要求**：两处改为 5xx（handler 内异常用 500；401/403 保持原样，**不得改动各路由显式返回的状态码**），
响应体结构不变（前端只读 `ok` 字段，不受影响），新增测试断言「已注册接口内部抛异常 → 5xx 且 `ok==false`」，
全量测试 `failed=0`（基线 203）。
